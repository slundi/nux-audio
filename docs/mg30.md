# NUX MG-30 Protocol Reference

Reverse-engineered from hardware captures using firmware **5.0.2 GEN2**.
GEN2 differs from fw 4.0.3 (the basis of the [mg30-controller Dart app](https://github.com/sirosss/mg30-controller)).

---

## Device Identity

- **Device ID:** `0x09`
- **Manufacturer byte:** `0x43` (Yamaha SysEx namespace)
- **MIDI port:** `NUX MG-30:NUX MG-30 MIDI 1 32:0`
- **Signal chain:** wah → comp → efx → amp → eq → gate → mod → delay → reverb → ir → vol (11 slots)

---

## SysEx Framing

All SysEx messages use the following wire format:

```
F0  43  <payload bytes>  F7
```

`send_sysex(payload)` in code prepends `F0 43` and appends `F7` automatically.

## SysEx Commands

### Version Query
```
Request:   F0 43 58 00 F7
Response:  F0 43 58 10 <version string> F7
           Response pattern: [F0, 43, 58, 10]
```
Version string is ASCII, e.g. `76 36 30 32` = "v602" (displayed as v6.0.2 / fw5.0.2 GEN2).

### Current Preset — Basic
```
Request:   F0 43 58 70 15 00 F7
Response:  F0 43 58 70 15 02 <data> F7
           Response pattern: [F0, 43, 58, 70, 15, 02]
```

**GEN2 response layout (15 bytes total):**

| Byte | Field | Notes |
|------|-------|-------|
| 6 | Preset slot | 0x00–0x7F |
| 7–8 | Unknown | Stable across BPM changes in tests |
| 9 | Active scene | 0=A, 1=B, 2=C, 3=D |

### Current Preset — Detail
```
Request:   F0 43 58 70 0B 00 <slot> 00 00 00 00 00 00 00 F7
Response:  F0 43 58 70 0B 02 <data> F7
           Response pattern: [F0, 43, 58, 70, 0B, 02]
```

**GEN2 response layout (222 bytes total):**

> fw 4.0.3 was 218 bytes — GEN2 adds 4 bytes, shifting most field offsets by +4.

| Bytes | Field | Notes |
|-------|-------|-------|
| 6 | Preset slot | 0x00–0x7F |
| 144 | BPM sync state | 0x00 = sync off, 0x06 = sync on (empirical) |
| 147 | BPM value | `BPM = (byte + 128) / 2` — confirmed at 98 and 120 BPM |
| 169–192 | Preset name | 24 bytes, 3-byte pair encoding (see below) |
| 147–168 | Effect chain / model data | Stable across presets; exact encoding TBD for GEN2 |
| 19 | Delay bypass | active=`0x00`, bypassed=`0x40` (bit 6 flag) |
| 20 | Reverb bypass | active=`0x00`, bypassed=`0x01` (bit 0 flag) |
| 21 | Reverb model ID | `0x00`=Room, `0x04`=Hall, `0x06`=Plate, `0x08`=Spring, `0x0A`=Shimmer, `0x0C`=Damp — all confirmed; used directly as catalog key |
| 22 | IR bypass | active=`0x01`, bypassed=`0x41` (bit 6 flag) |
| 23 | Unknown state byte | `0x00` or `0x01`; changes with some bypass combinations |
| 24 | Unknown (IR model?) | `0x7E` stable across all observed states |
| 208–220 | Scene on/off state | 3 scenes × 3 bytes each; exact offsets TBD |
| 221 | `F7` | SysEx end |

**BPM encoding:**
```
stored = BPM * 2 - 128
BPM    = (stored + 128) / 2

Examples:
  BPM  98 → 0x44  (sync off)
  BPM 120 → 0x70  (sync on)
```

**Name encoding (3-byte pairs, same as fw 4.0.3):**
```
bytes[n]   → first char (raw ASCII)
bytes[n+1] → flag (1 = add 0x40 to second char)
bytes[n+2] → second char = bytes[n+2] / 2  (+0x40 if flag=1)

Stop when bytes[n] == 0x00.

Example — "AA" (two A's):
  41 01 02  →  'A'  +  (02/2 + 0x40) = 65 = 'A'
```

### Change Preset
```
Request:  F0 43 58 09 20 <slot> <scene> F7
  slot:   0x00–0x7F
  scene:  0x00–0x03 (A–D)
```

### Request Effect Order
```
Request:   F0 43 58 70 0C 00 F7
Response:  F0 43 58 70 0C 02 <data> F7
           Response pattern: [F0, 43, 58, 70, 0C, 02]
```
Effect order byte layout in GEN2 TBD.

### Set Tempo (BPM)
From Dart app (fw 4.0.3, unverified for GEN2):
```
F0 43 58 70 03 01 <high> <low> 03 00 00 00 00 00 F7
  tempo_ms = high * 128 + low
  BPM      = 60000 / tempo_ms
```

### Save Preset
```
F0 43 58 70 7E 02 00 00 <slot> 00 00 00 00 00 F7
```

### Looper Control
```
F0 43 58 09 70 <cmd> F7
  cmd: 0x00=stop, 0x01=record, 0x02=play, 0x03=overdub
```

### Effect Model Switch
```
F0 43 58 09 30 <category_id> <model_id> F7
```
Confirmed working on GEN2 (tested: reverb category 0x08, models 0x30–0x35).

## MIDI CC Assignments

CC messages use standard MIDI: `B0 <cc> <value>` (channel 1).

### Bypass / Enable per slot

**Confirmed working on GEN2 hardware.**

| Slot | CC | On value | Off value |
|------|----|----------|-----------|
| Wah | 0 | 0x7F | 0x00 |
| Comp | 1 | 0x7F | 0x00 |
| Efx | 2 | 0x7F | 0x00 |
| Amp | 3 | 0x7F | 0x00 |
| Eq | 4 | 0x7F | 0x00 |
| Gate | 5 | 0x7F | 0x00 |
| Mod | 6 | 0x7F | 0x00 |

| Reverb | 8 | 0x7F | 0x00 |

> CC sends are confirmed to reach the device and change values.

### Scene Change
```
B0 4F <scene>   scene: 1=A, 2=B, 3=C
```

### Pedal / Expression
```
B0 4A <value>   (0–127)
```

## Bypass Byte Map in Detail Response (GEN2, Scene A)

Derived from controlled hardware diffs: capture reverb-ON vs reverb-OFF after save, diff the 222-byte detail response.

> Byte offsets are 0-indexed from start of full SysEx response (including `F0 43 58 70 0B 02` header).

Bypass encoding is NOT uniform. Some effects use **bit 6** (`0x40`) as the bypass flag; others use **bit 0** (`0x01`). Remaining bits in the bypass byte encode other state (model ID, scene flags, TBD). Companion byte (one position before) sometimes also changes.

Bypass encoding: **bit 6** (`0x40`) for effects with model data packed in bits 0–5; **bit 0** (`0x01`) for simple effects. Active value encodes model ID in bits 0–5 for bit-6 effects.

| Slot | Byte | Active | Bypassed | Flag | Status |
|------|------|--------|----------|------|--------|
| Wah  | 8  | `0x00` | `0x01` | bit 0 | Confirmed |
| Comp | 10 | `0x3F` | `0x7F` | bit 6 | Confirmed |
| Efx  | 11 | `0x00` | `0x01` | bit 0 | Confirmed |
| Amp  | 13 | `0x01` | `0x41` | bit 6 | Confirmed |
| Eq   | 14 | `0x00` | `0x01` | bit 0 | Confirmed |
| Gate | 16 | `0x00` | `0x40` | bit 6 | Confirmed |
| Mod  | 17 | `0x00` | `0x01` | bit 0 | Confirmed |
| Delay | 19 | `0x00` | `0x40` | bit 6 | Confirmed |
| Reverb | 20 | `0x00` | `0x01` | bit 0 | Confirmed (isolated: reverb ON→Hall changed byte 20 only) |
| IR   | 22 | `0x01` | `0x41` | bit 6 | Confirmed |
| Vol  | 25 | `0x01` | `0x41` | bit 6 | Confirmed |

> **Corrections:**
> - Byte 19 = **Delay** bypass (bit 6; `0x40` when bypassed) — previously mislabeled "delay companion"
> - Byte 20 = **Reverb** bypass (bit 0; `0x01` when bypassed) — previously mislabeled "delay bypass"
> - Byte 22 = **IR** bypass (not reverb)
> - Byte 23 = unknown state byte (not reverb)

**Reverb model** stored at byte 21 (separate from SysEx model IDs):
| Room | `0x00` |
| Hall | `0x04` |
| Plate | `0x06` |
| Spring | `0x08` |
| Shimmer | `0x0A` |
| Damp | `0x0C` |

**Reverb knob data** in detail response: bytes 114–120 (5 bytes; exact layout per model TBD).

**Also confirmed:** basic response (15 bytes) byte 7 reflects combined bypass status (exact bitmask TBD).
